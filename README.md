# Shell Emulator — вариант 12

Практическая работа «Конфигурационное управление», ИКБО-22-25.
Текущий этап: 4. Python 3.12+, консольный интерфейс Windows.
Внешние библиотеки для работы программы не требуются, сборка не нужна.

## Установка, запуск и тесты

Откройте эту папку как проект PyCharm. Создайте Python-окружение `.venv`
в настройках интерпретатора или выполните из корня проекта в PowerShell:

```powershell
py -3 -m venv .venv
.\run.bat
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

`run.bat` передаёт все аргументы и код возврата, запускает из корня проекта;
использует `.venv`, затем `py -3` или `python`, если окружения ещё нет.
Прямой запуск: `python -m src.main`. Для него рабочая папка — корень проекта.
Настройки PyCharm и окружение локальны и не входят в Git.

## Структура и требования к коду

`src/` — приложение; `tests/` — unittest; `run.bat` — запуск;
`.gitignore` — исключение окружений, настроек редактора и сборки.
Во всех коммитах присутствуют тесты и README соответствующего этапа.
Ограничения: файл ≤1000 строк; Python-строка ≤80 символов; функция ≤40 строк;
аргументы ≤7; цикломатическая сложность ≤10. Используются docstrings,
snake_case и именованные значения в сравнениях. `tests/test_quality.py`
проверяет структуру и AST. При разработке проверяются flake8 и pep8-naming.

## Ввод и команды

Приглашение `default:~$` содержит имя VFS. Парсер разделяет ввод по пробелам
и другим пробельным символам. Кавычки и escape-последовательности команд
не поддерживаются по варианту 12: используйте виртуальные имена без пробелов.
Пустые строки игнорируются. Неизвестные команды и неверные аргументы
выводят `error:`; REPL продолжает работу. `exit` без аргументов завершает
сеанс. EOF и Ctrl+C также корректно завершают интерактивный ввод.

## Параметры и стартовые скрипты

`--vfs ПУТЬ` задаёт каталог-источник; `--script ПУТЬ` — стартовый UTF-8
скрипт. Параметры необязательны и выводятся при запуске. Пути параметров ОС
могут содержать пробелы, если заключить их в кавычки. Относительные пути
в `run.bat` считаются от папки проекта.
Startup печатает приглашение с командой и результат, останавливается при
первой ошибке с номером строки и кодом 1. Ошибка чтения тоже даёт код 1.
После успешного скрипта начинается REPL; exit в скрипте завершает процесс.

```powershell
.\run.bat --vfs vfs/several --script scripts/startup.txt
.\scripts\test_parameters.bat
.\scripts\test_parameters_alternate.bat
.\scripts\test_errors.bat
```

Оба BAT-скрипта параметров проверяют --vfs и --script отдельно и вместе.
Успешные команды находятся в `scripts/startup.txt`, ошибки — в отдельных
`scripts/error_*.txt`, чтобы остановка при первой ошибке не скрывала другие.
Строка `never_run` после ошибки не должна выполняться.

## Виртуальная файловая система

Источник — каталог на диске, не XML/архив. При загрузке все каталоги и
байты файлов считываются в память. Имя VFS — имя исходного каталога.
После загрузки команды работают только с памятью. Без --vfs создаётся
пустой корень с именем `default`. Отсутствующий путь, файл вместо каталога,
недоступные данные, ссылки/junction и специальные файлы дают ошибку загрузки.
Ссылки не поддерживаются, чтобы избежать циклов и выхода за дерево.

`vfs-info` без аргументов печатает имя и SHA-256 текущего дерева в памяти.
Хеш не зависит от порядка обхода, расположения исходной папки и времени
изменения. Алгоритм: отсортировать виртуальные пути; для каждого узла
хешировать тип (directory/file), путь UTF-8 и байты данных. Каждое поле
предваряется его длиной как 8-байтовым unsigned big-endian числом.
У каталогов байты данных пусты. Корень `/` также включается.

Примеры: `vfs/minimal` — один пустой файл; `vfs/several` — несколько файлов
и каталогов; `vfs/nested` — три вложенных каталога и файл на четвёртом уровне.
Каждый из двух `test_vfs*.bat` загружает все три варианта.

```powershell
.\run.bat --vfs vfs/nested --script scripts/startup_nested.txt
.\scripts\test_vfs.bat
.\scripts\test_vfs_alternate.bat
```

## Основные команды

- `ls [путь]`: отсортированные имена в каталоге; для файла — его имя.
- `cd [путь]`: переход в каталог; без аргументов — корень.
- `pwd`: абсолютный виртуальный путь.
- `date`: текущие локальные дата и время; `date -u` — UTC.
- `cal`: текущий месяц; `cal ГОД` — год; `cal МЕСЯЦ ГОД` — указанный месяц.
  Неделя начинается в понедельник, год 1–9999, месяц 1–12.
- `vfs-info`, `exit`: без аргументов.

Виртуальные пути используют `/`; поддерживаются `.`, `..`, абсолютные и
относительные пути. Выше корня перейти нельзя. Другие опции не поддержаны
и вызывают ошибку. Календарь использует стандартный модуль Python calendar.

## Интерактивная демонстрация ошибок

```text
ls
cd .
unknown
cd a b
exit extra
exit
```

Для этапов 4–5 дополнительные успешные и ошибочные режимы собраны
в startup-скриптах. Очная демонстрация на защите выполняется студентом.

## Функции приложения

### commands.py

- `list_command` — Выводит имена каталога либо имя указанного файла.
- `change_directory` — Меняет рабочий каталог; отсутствие аргумента означает корень.
- `print_directory` — Печатает текущий абсолютный путь внутри VFS.
- `date_command` — Печатает локальную дату/время или UTC для флага -u.
- `calendar_command` — Печатает текущий месяц, заданный год или заданный месяц года.
- `run_command` — Выбирает основную команду по имени.

### config.py

- `parse_arguments` — Разбирает необязательные --vfs и --script.

### errors.py

- `validate_count` — Проверяет число аргументов по множеству разрешённых значений.

### main.py

- `run_interactive` — Выполняет REPL до exit, EOF или Ctrl+C.
- `main` — Запускает эмулятор и возвращает код завершения процесса.

### parser.py

- `parse_command` — Возвращает команду и аргументы; кавычки не интерпретируются.

### shell.py

- `__init__` — Создаёт сеанс с именем виртуальной файловой системы.
- `prompt` — Возвращает приглашение с именем VFS.
- `execute` — Выполняет команду, преобразуя ожидаемые ошибки в статус.
- `_dispatch` — Вызывает доступную команду или сообщает о неизвестной.

### startup.py

- `run_startup` — Печатает ввод и вывод, возвращает статус последней команды.

### vfs.py

- `__init__` — Создаёт пустую файловую систему по умолчанию.
- `load` — Заменяет состояние только после успешной полной загрузки.
- `resolve` — Находит существующий путь, проверяя каждый компонент.
- `require_directory` — Отвергает путь к файлу вместо каталога.
- `fingerprint` — Хеширует сортированные пути, типы и точные байты с длинами.

### vfs_loader.py

- `is_link` — Обнаруживает символические ссылки и Windows junction.
- `read_directory` — Рекурсивно считывает обычные файлы и каталоги без записи на диск.
- `load_snapshot` — Возвращает имя и дерево источника, сообщая об ошибках чтения.

`reject_options` отвергает неподдерживаемые опции ls/cd.
